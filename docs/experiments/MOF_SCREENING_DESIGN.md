# MOF 筛选程序自动改进：实验设计草案

**状态：实验实施已获授权，正在转为可运行协议；截至本次更新尚无 MOF 实验结果。**
日期：2026-10-12。算法依据：[Dream-RSI v2 第三章](https://arxiv.org/abs/2609.14858v2)。本方案独立设计应用实验，不复用论文第四章任务。

预算与并发修订：将早期草案的 2 workers 和每方法每区组 1M 正式 token 上限调整为 **8 workers、30M token**，并同步增加外层世界数、每世界轮数、策略候选数和发现 session 上限。以下仍是待实施的计划；预算没有消耗，充足性尚未经测量。

## 1. 实验要回答什么

结合公司已有的 MOF 材料业务背景，选择一个可以从公开数据开始、以后接入公司计算流程的任务：**让 Pi 自动改进一个 MOF 筛选程序，从未知吸附标签的材料池中推荐前 10 个材料。**

主问题：在相同模型、数据、工具和允许的 token 预算下，Dream-RSI 是否比固定搜索策略产出更好的筛选程序？策略开发、语法修复和失败请求的成本都计入。

预先区分两个结论：

1. **主要研究：完整工作流的效果。** 学习搜索策略的开销是否值得，最终程序能否筛出更好的未见材料？
2. **后续研究：冻结策略的迁移。** 学到的 `π_N` 能否帮助新任务的程序搜索？本阶段不据主研究结果自动宣称这一点。

第一阶段使用公开的模拟吸附数据，得到的是“在指定模拟参考条件下筛选已收录材料的能力”。工业工况、湿度稳定性、合成可行性、成本、循环寿命和真实混合气分离均需后续数据支持。

### 三类对象

| 对象 | 在实验中的含义 |
| --- | --- |
| MOF | 筛选程序要排序的材料，一行特征对应一个材料 |
| 树节点 | 一次 Pi 代码修改后得到的完整候选程序及其开发集评分 |
| 搜索策略 `π` | 根据已观察到的代码搜索树，决定下一批修改哪些父程序，或停止 |

程序学习材料的结构—性质关系；Dream-RSI 学习如何搜索这些程序。

## 3. 任务与评分契约

### 3.1 固定的第一阶段目标

推荐 **CO₂、298 K、1 bar（100000 Pa）、UFF + DDEC** 下绝对吸附量最高的 10 个 MOF。这是一个可解释的初始筛选目标，条件选择属于本方案，不表示已经确认公司的具体产品工况。

第一阶段采用这一种参考条件，保持物理模型一致。其他力场、电荷、温度或压力不作为训练增强数据；后续可作为稳健性研究。纯组分 CO₂/N₂ 吸附量之比不能直接报告成混合气选择性。

### 3.2 交给 Pi 的材料

- 固定任务说明、字段和单位说明、环境及可用包清单。
- 训练集 `train_features.csv`、`train_targets.csv`：可以看到标签。
- 开发池 `dev_features.csv`：可以看到特征；标签由独立评分器持有。
- 一个有效的起始 `candidate.py`，实现固定的训练集中位数填补 + 标准化 + Ridge（`alpha=1.0`）回归排序；训练列全空时丢弃该列，并在其他池使用同一字段变换，不经最终测试集选择。
- 分支完整历史和先前世界的公开反馈，遵守现有 v2 上下文机制。

目标是改进特征处理、监督学习与排序方法。允许包建议固定为 Python、NumPy、pandas、scikit-learn；具体版本在实施时锁定。候选不能安装包、联网查标签、读取评分器文件或修改评分器。

第一阶段不传入吸附焓、别的压力/温度的吸附量或由吸附量推导的特征。材料使用不透明 ID；不把原始材料名、来源路径或真实标签写入可见任务。

### 3.3 候选程序接口（设计，尚未实现）

```python
def rank(train_X, train_y, pool_X, *, k: int, seed: int) -> list[str]:
    """仅用训练标签拟合，返回 pool_X 中 k 个不重复材料 ID，按推荐顺序排列。"""
```

`train_X` 和 `pool_X` 使用同一字段表；ID 不作数值特征。`train_y` 单位为 mol/kg。填补、标准化、特征选择和超参数选择只能在训练集内部拟合；候选可自行做训练集交叉验证。程序须支持任意合格材料池，不能依赖固定行序或硬编码开发池 ID。

每个候选在干净进程中执行，拟合及排序总计建议上限 120 秒、2 个 CPU 核、2 GB 内存；所有方法一致，超时计失败。禁止外部网络，最终测试不向候选挂载标签。限制实施是否可靠要先验收；当前 Windows 进程管理本身不提供标签隔离。

### 3.4 唯一的节点任务分数

对材料池 `D`，固定 `K = 10`，候选推荐集合为 `A`，私有标签为 `q_i`：

```text
Q(A) = (1/K) × Σ[i in A] q_i                         # 原始推荐平均吸附量，mol/kg
Q*(D) = D 中真实吸附量最高的 K 个材料的平均吸附量       # 私有参考上界
S(A,D) = Q(A) / Q*(D)                               # 节点分数，正常落在 [0,1]
```

按固定材料 ID 打破真实标签相同的排序并列。若 `Q*(D) <= 0`，该数据任务不合格；若正常推荐分数超出容差，报告评分器错误，不用裁剪掩盖解析问题。

输出缺失、重复 ID、池外 ID、异常或超时：`status = failed`、`S = 0`。有效但很差的程序仍保留实际分数。评分器不能接受候选自报分数。

公开反馈只含开发池的 `S`、成功/失败状态和契约错误种类；不公开逐材料残差、标签、真实前 10 名或参考上界。训练集内部的验证结果可由 Pi 自己计算。原始 `Q`、不确定性及详细排名保存为私有分析材料。

论文 Eq. (1) 的 `V` 仍按 v2 原式计算，使用历史世界的节点分数；`V` 是选择 `π` 的内部依据。实验成功与否看最终测试池的 `S`、原始 `Q` 和成本。

## 4. 划分、隔离与最终解封

### 4.1 材料分组划分

先用固定 seed `20261012` 按材料组封存约 **30% 的永久最终测试集**，其余 70% 为工作数据。在工作数据内部用五个 split seed 按 `5:2` 分出训练集和开发反馈池，得到约 **50% 训练 / 20% 开发反馈 / 30% 最终测试**。最终测试材料在所有划分、所有预实验中均不可用作训练或开发；五个划分共享同一个封存测试池。

最终实际数量由分组决定。若 690 个材料全合格且没有合并，数量约为 345/138/207，这只是规模示例。预实验只使用 70% 工作数据的前两个训练/开发划分。

分组规则先于任何程序搜索固定：

1. 同一材料的所有温度、气体、力场、电荷版本必须同组。
2. 可识别的相同来源 refcode 家族、结构重复及相同完整描述符行合并为组；结构核验方法、容差和版本写入清单。
3. 不能识别的近似结构列为残余泄漏风险；第一阶段的分组随机划分不等于拓扑、连接体或金属家族外推。
4. 按组进行确定性随机划分，冻结 split seed 和完整 ID 清单。不用吸附标签做平衡或挑选“好”的划分。

正式探索研究使用 split seeds `101, 211, 307, 401, 503`；每个划分做两个独立搜索重复，运行标识 `1, 2`，共 10 个配对区组。运行标识不能保证模型服务随机种子可控；所有服务端参数和版本可见信息照实记录。

| 训练特征与标签 | 可见 | 不额外给予标签，只给公开历史 | 可见 |

原始公开数据库在正常联网环境下可以查到标签，因此搜索环境还要拒绝联网和挂载原始等温线；不透明 ID 只能减轻直接查表，不能证明模型未记忆公开数据。

每次运行只挂载自己的训练集和开发特征。其他划分的训练标签、其他方法的树与代码、其他搜索重复的历史均不可见；方法之间不交换发现结果。先前世界上下文只来自当前运行。这样避免某个划分的开发标签从另一个划分的训练文件进入上下文。

### 4.3 候选冻结与选择

所有方法在相同预算检查点选择当时开发 `S` 最高的已完成候选，跨该运行全部世界选择；相同分数优先更早完成者。起始程序参与最终候选选择，但不计成非根发现节点。没有有效改进时保留起始程序，并报告失败率。

先冻结所有方法、所有重复、全部检查点的候选哈希、策略哈希、选择规则和成本日志，再批量解封测试集。候选用同一训练集重新拟合，不能加入开发标签。只评价事先选定的候选，不在测试集上给所有树节点打分后重新选冠军。

解封后不修改任务、指标、模型、过滤规则或候选；必要修改另立版本，并安排新的独立最终验证。两个阶段的开发池重复反馈可能过拟合，最终测试正是用来揭示这种现象。

## 5. 对照、算法参数与预算

### 5.1 三个 Pi 方法

| 方法 | 策略 | 用途 |
| --- | --- | --- |
| A：Dream-RSI | 由同一 Pi 模型逐轮改写并回放选择 `π` | 实验方法 |
| B：固定初始策略 | 全程冻结仓库 `policies/incumbent.py`，相同世界历史、W 与上下文 | **主要对照**，直接检查学习策略是否值得 |
| C：固定串行策略 | 每次改写最高开发分数的合法叶子；没有叶子则从根开始；并列规则固定 | 辅助对照，衡量搜索方式与并行的影响 |

B 不调用策略开发者，省下的 token 可在允许的发现上限内用于代码搜索。C 使用相同 Pi 模型、训练数据、反馈、初始程序和全部先前世界历史。B、C 的策略代码在正式研究前冻结，不根据结果人工修改。

另给出四个材料筛选参照：随机排序（种子 1–100）、可访问比孔容（cm³/g）降序、上述固定 Ridge、固定随机森林（300 棵树、`min_samples_leaf=2`、`max_features=1.0`、`random_state=20261012`、`n_jobs=2`）。随机森林使用同样的训练集中位数填补，不做标准化。两个学习参照均只在训练集拟合。它们说明任务难度，不冒充有相同模型调用预算的 Pi 对照；字段映射与具体环境在数据适配后、最终解封前固定。

### 5.2 算法参数

**同时执行的层次：** 每次只运行一个区组中的一个方法；A/B 每轮最多 8 个独立 Pi 发现 session，各自修改不同合法父节点的工作区，当前批全部结束后才进入下一轮。8 是容量上限；初轮只有根节点时只能运行 1 个，之后也可能因合法节点数量、策略选择或预算而少于 8 个。C 始终最多 1 个发现 worker。

策略开发与发现分阶段进行；每份策略修订依次生成、回放、反馈，然后才生成下一份，最多同时 1 个策略开发 session。回放不占 Pi workers。不同方法、区组和重复不并行执行，因此整个实验的同时发现 session 上限也是 8，而不是 `3 × 8` 或 `10 × 8`。

每个发现 worker 对应一条“Pi 修改程序→独立评分”流水线，2 CPU 核是评分阶段的配额，不是额外的 Pi worker。若 8 个评分同时运行，按本方案配额最多合计 16 CPU 核、16 GB 评分内存，另需计入 Pi/运行器开销；实施前核验本机资源和服务并发限制。若资源不能支撑，须在正式研究前修订配额或并发，A/B 一致，不能在正式研究中途悄悄更改配置。

增加 W 也要增加世界长度：合法动作是根和叶子，单个父节点每批只扩展一次。初始只有根时，workers 数量不能立即变成实际并发；例如固定初始策略持续保留根探索时，前几轮的实际宽度逐渐从 1、2、3 增长。正式 K₁=12 给到达较宽前沿后的搜索留出轮数。8 workers 是否降低墙钟时间，还受最慢 worker 的批次等待、模型服务限流和本地评分资源影响，预实验必须测量。

| 参数 | 小规模预实验（将来） | 正式探索研究（将来） |
| --- | --- | --- |
| 世界数 `N` | 2 | 8 |
| A/B 的 `W` | 8 | 8 |
| A/B 的 `K₁`, `K₂` | 8, 8 | 12, 12 |
| C 的 `W`, `K₁` | 1, 64 | 1, 96 |
| A 的 `M` | 2，包含 incumbent | 3，包含 incumbent |
| A/B live `ρ` | 1 | 1 |
| 回放 `ρ` | `{0, .25, .5, .75, 1}` | 同左 |
| `λ` | 0.1 | 0.1 |
| 配对区组 | 2 个，仅用开发数据 | 5 个划分 × 2 个重复 = 10 个 |

参数是本实验的选择，不是论文规定的唯一取值。A 预实验每次选择最多一份新策略，正式研究每次选择最多两份依次修订的新策略；包含最后一次离线选择，共最多 `N × (M−1)` 次策略开发，即预实验 2 次、正式 16 次。回放无模型或材料评分调用。世界之间使用同一 TaskSpec 和根程序，历史照常传递。这与当前控制器能力一致；不能把同一任务的多个世界写成跨任务训练。

最后一次离线选择产生的 `π_N` 没有再生成本阶段材料筛选程序，它的成本仍包含在 A 中；其用途在后续冻结策略研究中单独评价。

### 5.3 预算与真实成本口径

默认**计划值，未授权启动**：预实验每方法每区组 **5,000,000** 个总 token，正式研究每方法每区组 **30,000,000** 个总 token。这里是一次完整方法运行的共享预算，不是每个 worker 的额度。总 token 为所有实际服务请求的输入与输出之和；推理 token 按提供商输出统计口径计入，缓存输入也记录。

- 预实验合计允许上限：`3 × 2 × 5,000,000 = 30,000,000` token，即 3000 万。
- 正式探索研究允许上限：`3 × 10 × 30,000,000 = 900,000,000` token，即 9 亿；一个正式配对区组的三个方法合计最多 9000 万。
- 额外设置发现 session 上限：预实验每方法每区组 128，正式 768，与 `N × K₁ × W` 的容量上界一致。
- A 的策略开发逻辑调用上限另为 2 / 16，因此全部方法的发现/开发逻辑调用总上界为预实验 772、正式 23,200。根节点初期合法动作较少、主动停止或 token 耗尽都会使实际数量更少。
- **一个 Pi session 可能包含多个服务请求，策略语法修复还可能开启额外 session**。上述策略开发上界按一次 `propose` 计数，不含修复 session；修复、工具后续请求和失败请求全部计入 token 与费用。逻辑调用上界不是实际 Pi session 或 API 请求上界。

主要比较的是相同**允许总 token**，实际耗费单独报告。若要声称“相同金额下更好”，必须增加实际计费的共同检查点分析，纳入输入/输出不同费率、缓存、策略开发与修复；缺失账单只能报告 token，不能编造人民币/美元费用。

建议正式 token 检查点为 1M、2M、5M、10M、20M、30M；预实验为 500k、1M、2M、5M。只使用在检查点预算以内已完成且选择规则确定的候选，不能倒用其后完成的程序。提前停止的运行在后续允许预算上保持原候选，并报告实际停止成本。

旧草案 1M 正式预算若分摊到最多 64 个发现调用加 4 个策略开发调用，平均仅约 14,700 token/逻辑调用，其中还包括历史输入和工具往返。这个算术比值不是实测消耗，但显示旧额度缺少余量。新方案 30M 分摊到最多 768 个发现加 16 个开发调用，约 38,300 token/逻辑调用；这也不是单 session 限额或充足性保证。

将来预实验需要分别测量发现与策略开发的 session token 分布、历史增长、完整外层迭代完成率、预算截断位置和批次等待时间。依这些结果在不解封最终测试集的前提下校准并冻结正式预算；若连充分的完整迭代都无法完成，先修订协议。仅提高 token 而保留很小的 N、M 和发现数量，不能增加可供策略学习的历史证据。

预算实施需支持逐服务请求记账、并行请求预留及 session 内的硬上限。A 还须预留后续策略开发的预算；若硬限导致缺少正常应有的选择，保留并标记 `budget-cut`，不能报告为完整 N 轮运行。不得用延长预算给 A 补齐后再与原预算的 B/C 比较。

现有 `CallBudget` 数的是发现/开发 session，**还不能落实上述 token 硬限**。这是实验实施前必须完成的功能。

模型计划沿用已验收的本机 Pi 配置 `cc-switch-deep-seek / deepseek-v4-pro`；启动前固定并记录提供商、可见模型版本、Pi 版本及服务参数，三个方法一致。各方法执行顺序在区组内预先随机化，减轻服务波动影响。

发现和策略开发 session 的墙钟上限建议统一为 900 秒。两种上限、候选评分时间和 token 硬限分别记账；时间到期时保留已发生的成本和失败状态，不免费重试。

## 6. 如何判读结果

### 6.1 指标与统计单位

**唯一主要效果指标：** 最终测试池在 30M 允许 token 下的 `S`，主要比较 A−B。同时报告原始推荐平均吸附量 `Q`，让差异能解释为 mol/kg。

辅助指标：前 10 推荐中的真实高性能材料命中数（测试池真实排名前 `ceil(0.1 × 材料数)` 为高性能，并列按 ID）、各预算检查点质量、开发—测试差距、失败率、实际 token/计费、候选执行成本、总耗时和最大并发。另对测试池行序做预定的三次重排，检查同一程序能否返回一致材料推荐；只作契约诊断，不挑选最有利结果。C 的结果、其他指标与所有策略内部 `V` 曲线均为辅助分析。

统计单位是完整的配对搜索运行。五个回放 `ρ`、树节点和单个材料不是独立重复。先在每个划分内汇总两个搜索重复的 A−B，再展示五个划分差值及总均值、中位数、范围；可按划分整组 bootstrap 给探索性的 95% 区间，保留配对与组内重复。

不同训练/开发划分来自同一有限材料库且会重叠，并共享最终测试池，五组也很少；区间只反映该设计下的波动，不能当成对所有 MOF 的高把握度证明。此规模是正式记录的探索研究，后续独立数据库或公司材料验证再作确认。

### 6.2 预先规定的结果解释

- 若 A−B 平均至少 **0.05 个 S 单位**、方向在至少 4/5 划分一致，并且探索性区间不跨 0：记为有进一步验证价值的效果。0.05 是本方案预设的实践门槛。
- 若区间跨 0：报告证据不足；若 A 明显更差或更贵：报告负结果。不能把 `V` 上升改作主成功标准。
- 若开发提升而测试不提升：报告对开发反馈过拟合的迹象。
- 若固定学习参照的开发 S 已接近上限（建议 ≥0.95），预实验阶段可判断任务饱和；先修订方案，例如降低训练标签量，再冻结新的正式协议。最终测试仍不解封。
- 无论成功与否，保留所有预算截断、生成失败和合法提前停止运行。服务故障发生后按预先规则记录/恢复，不删掉“看起来不好”的重复再补一个。

启动后外部中断只在能够确认未重复计费、未改变模型及冻结协议时原地恢复。否则标记不完整，单列可用成本与候选；配对主表同时展示完整区组数及包含失败/截断的结果，不暗中剔除。

## 7. 实施顺序与交付物

### 7.1 审阅后才开展的工作

1. **数据适配。** 下载并校验固定数据；解析字段/单位和 MOF 来源；生成分组、过滤及划分清单；实现公开输入/私有标签边界。
2. **任务和评分器。** 增加 `mof_screening` TaskSpec、候选接口、固定种子程序、私有评分器和最终批量解封工具；评分器不得由 Pi 改写。
3. **实验运行器。** 增加三个方法、区组执行、统一预算、逐请求账本、检查点候选冻结；当前 CLI 只注册 knapsack，尚不能直接启动本设计。
4. **实施验收。** 将来检查单位、目标压力取值、无标签泄漏、无重复候选 ID、失败分数、预算截止、配对配置与回放零外部调用。验收只验证实现，不提供效果结论。
5. **预实验。** 只用训练/开发数据评估可运行性、耗时、任务是否饱和和预算可行性。先更新协议/配置并冻结，再开展正式研究。
6. **正式研究和统一解封。** 全部候选与账本冻结后才计算最终指标，形成正结果或负结果报告。

实施可按正常分支、commit、PR 流程完成。数据文件、账户配置和运行记录不跟随文档提交混进代码许可；归属和数据许可单独保存。

### 7.2 结果总结与可视化

每次完成预实验或正式研究，都必须产出一份面向读者的结果总结和可复查的数据图，不把结论留给读者从日志中拼出来。总结必须明确回答主问题：Dream-RSI 相对冻结策略的最终测试效果差异、区间、总 token/费用、失败与截断情况，以及结论属于正向证据、证据不足还是负结果；同时列出数据版本、运行完整度和主要限制。不得用内部 `V` 上升替代材料筛选效果。

图形沿用 v2 论文结果图的表达逻辑：Figure 3 用随 discovery generations 推进的阶梯轨迹比较方法；Figure 4(b) 用累计 discovery compute 展示递归轮次的动态，并标出轮次；Figure 5(a,b) 将 best-so-far 发现过程与全套任务上的最终对比并列。对本实验作以下对应：

1. **筛选质量—预算阶梯图**：横轴累计 Pi token（同时标注 discovery 调用数），纵轴开发池的 best-so-far `S`；按方法画配对运行轨迹及跨区组汇总区间，外层世界用标记注明。测试集指标不参与轨迹或候选选择。
2. **递归动态多面板图**：每个面板一个 split seed，画最终测试池的预算检查点质量 `S` / `Q` 对累计 token；A、B、C 使用一致检查点，标注外层世界，显示 Dream-RSI 相对固定策略何时开始拉开差异。
3. **最终方法配对图**：展示每个材料划分的 A、B、C 最终测试 `S`，以配对线连接 A 与 B；同时给出 `A−B` 的按 split 整组 bootstrap 95% 探索区间和预设的 0.05 实践门槛。
4. **筛选结果解释图**：比较每种方法前 10 推荐的 CO₂ 吸附量分布，并显示随机、比孔容和固定 Ridge / Random Forest 参照；把原始 `Q`（mol/kg）与归一化 `S` 分开标注。
5. **算法机制图**：另画内部 Eq.(1) `V` 随外层轮次变化及树的 best-so-far `S`，用于解释策略演进；图注明确 `V` 是内部策略指标，不能作为材料筛选成功的证据。

输出 PNG 供快速阅读，同时保存 SVG 或 PDF 矢量版、生成图用的 CSV/JSON、以及带数据版本/运行配置/置信区间/结论边界的 `summary.md`。若运行失败或数据检查未通过，应生成状态报告说明缺失项；不得制作暗示已有实验结果的图。

### 7.3 后续升级：冻结策略的迁移

主研究完成后另立协议：固定 `π_N`，在独立任务/材料池开展新的 Pi 程序搜索，期间不再调用策略开发者；比较冻结 `π_N` 与冻结 `π_0`，提供同样的历史上下文，防止把历史代码收益算成策略收益。新任务也需要独立的训练/反馈/最终验证三部分。
